# Microvoxel World Lab

Open `prototypes/microvoxel-world.html` through `npm run serve`, or the **Microvoxel World** Exploration entry in the playtest library. No build or external runtime dependencies. WebGL2 and workers are required. This is an engineering/visual proof for [Epic #8](https://github.com/Thaumonaut/Spacology/issues/8), with bounded worlds and an opt-in streaming experiment, not a replacement for the world editor, voyage, Supply Run or route-planning prototype.

Do not double-click the repository's source HTML: browsers block its separate worker under `file://`. From the repository root, run `npm run serve` and open `http://localhost:4173/prototypes/microvoxel-world.html`. For a desktop file that needs no server, run `node tools/package-microvoxel.cjs /existing/directory/world.html` and open that output instead; it embeds its worker. Do not disable browser security. iOS Files/Quick Look is still not a supported launch path.

Dialog dismissal, Generate and Travel use direct button handlers rather than native form submission, so a script-enabled embedded preview does not need `allow-forms`. Numeric inputs still use native validation and Enter works. The retained launch regression uses an opaque `sandbox="allow-scripts"` iframe, without broadening its permissions.

## World truth

- 128 × 128 metres by default; the optional **256 × 256 m region** extends the same seeded geography to four times the area. Y up. The default uses 0.25 m material cells (32 × 32 columns, 96 vertical cells per chunk). The **12.5 cm** comparison uses 0.125 m cells (64 × 64 columns, 192 vertical cells). Both cover the same 8 × 8 × 24 m chunk volume; trees, ore thickness, water and characters retain their metre scale.
- Seed + generator revision + coordinates determine strata, terrain, water and volumetric vegetation. Material run endpoints retain occupied/empty intervals, not just a rendered heightfield. Surface geography is intentionally simple in this proof: one ridge, river catchment and clearing. This is not yet planet geology, caves or production generation quality.
- `createWorld(seed, cellMetres = 0.25, extent = 128)` exposes ground/column/chunk queries and the already-surveyed ferrite root. The root lies on fault-exposed basalt; its stable ID/provenance is independent of mesh/cache state. Trees are derived from a bounded coordinate grid and cached, not randomly advanced per request. Both densities and footprints retain the root identity and existing 128 m material truth; `dataId` additionally identifies cell size **and footprint**, since a formerly out-of-bounds edge chunk's mesh halo changes on expansion. Density regeneration changes authoritative ground quantization, unlike render-only LOD. Ground returns `null` outside the selected footprint, which selection skips rather than intersecting nonexistent terrain.
- No mutation/editing API. Ground queries use exact voxel-column centres and exclude foliage; water surface is not walkable ground. The demo actors stay in the dry clearing. No pathfinding, road validity, construction, discoveries or Research handoff is implemented yet.

## Data/render path

1. The worker retains lossless column runs (`Uint16` offsets, byte endpoints/material IDs) in an LRU capped at 128 chunks / 4 MiB. One request is in flight; the current view replaces queued work. Completed work remains useful across view changes when its `dataId` matches and the chunk/LOD is still needed. Old-seed/density/footprint results and errors cannot populate or fail the replacement world; offscreen results are discarded. A pointer event no longer invalidates all pending work, which previously starved 12.5 cm loading during a continuous drag.
2. A transient dense halo samples the same world outside each chunk. Greedy meshing merges only coplanar, same-material exposed faces. No internal voxel faces are submitted. Six vertices per quad use **8 bytes each** (local uint16 XYZ, byte face/material); buffer ownership transfers to the main thread.
3. The WebGL2 renderer uploads one buffer/VAO per mesh. The GPU chunk cache caps at 320 entries / 32 MiB and deletes buffers/VAOs on eviction. The original footprint has 256 horizontal chunks; the expanded footprint has 1,024, but only visible ones are generated and the regional zoom limit adapts to the screen aspect so a view stays inside the cache's entry budget. Pan to explore rather than loading the entire region at once. No per-cell objects/draw calls and no terrain meshing in the animation loop.
4. Camera span chooses a uniform cell-/half-/one-metre surface approximation. The finer density can use an 8× render step to retain metre-scale overview costs. The **previous LOD remains drawable** while new meshes stream; the displayed step switches after the requested view is fully resident. If both views cannot fit, retain one covering mesh per visible chunk, prioritizing requested meshes and retiring an old fallback only where a replacement exists. This avoids a cache-starvation loop as well as clearing the world on zoom; it is not geometric morphing or a crossfade. Previously unseen edge chunks can still stream in, with a visible indicator. Adjacent chunks use halo queries to avoid border faces; a settled view has uniform LOD to avoid mixed-resolution cracks, though a budget-constrained transition can temporarily mix steps. The highest occupied material in each vertical block preserves grass at coarse zoom. Approximation can shift a visible surface by up to a coarse cell; it is explicitly **not** construction ground. Switching density clears both caches and measurement samples; in-flight obsolete results cannot populate the new density.
5. Characters reuse a shared unit-cube mesh with articulated body-part transforms. They do not rebuild voxel meshes each frame. Fixed 50° downward orthographic tilt / 35° azimuth; drag/arrows pan, +/− zoom (down to an 8 m span), R returns to root, Space pauses. Drag uses the inverse projection so terrain follows the pointer horizontally and vertically; view scheduling is coalesced once per animation frame without adding drag inertia. Arrows travel relative to the screen (Up moves up-screen along the 35° view azimuth, not world north). Held arrows use frame-time movement, eased velocity and normalized diagonals from the first keydown, independent of OS key repeat, and settle within about 0.2 s of keyup. Arrows work whenever the page has focus (except text fields and open dialogs); a tap nudges 5 cm and window blur/modal opening stops travel. At 12.5 cm, newly exposed chunks first receive a cheap 4× coarser placeholder mesh (fine meshing dominates chunk cost), so fast drags show terrain before full detail replaces it. Buttons support touch. Reduced motion stops limb/water oscillation; Pause stops crew movement as well.

## Measurements and limits

**LOD pin.** The toolbar's **LOD** menu overrides the automatic choice. Finite worlds offer render steps of 1, 2, 4 or 8 cells. The streamed world offers every LOD level (one column every 2^L cells, 25 cm to 8 m at 25 cm density). The view label shows PINNED, and `?lod=v4` keeps the choice on reload. A pinned streamed level never coarsens; if its nodes cannot fit the GPU budget, the view narrows instead. Coarse-first loading is off while pinned, so the Performance panel measures that level alone.

Performance opens live frame p50/p95/p99, generation/meshing p95, resident voxel bytes, uploaded **chunk** vertex bytes, cache counts, useful meshes retained after a view change, coarse placeholders, draw calls and triangles. Export captures the world identity and browser/viewport. Frame intervals include visible-tab stalls; they are not GPU timestamps. Driver/framebuffer overhead, transient JS allocations and whole-process memory are not claimed to be measured. Shared actor geometry adds 288 vertex bytes outside the chunk cache. Economy caps pixel density at 1 and coarsens render sampling; ordinary density is capped at 1.5.

`node tools/benchmark-microvoxel.cjs [seed]` reproducibly measures 64 root-catchment chunks at full resolution, with hardware and revision in JSON. On this session's Linux Xeon / Node 24.19.0, seed 2718 used 623,726 encoded bytes versus 6,291,456 dense bytes (**10.09×** smaller). Greedy meshing emitted 25,642 quads for 177,447 exposed faces (**85.55%** fewer). These are exact fixture sizes, not universal compression ratios or phone-performance results. Cold generation/meshing timing varies with warmup and hardware; rerun the command rather than treating a VM time as a device budget. Warm lookup timing excludes remeshing.

### Finer-density comparison

The same seed-2718 fixture, 64 chunks and physical area on Node 24.19.0 / Linux Xeon:

| Full-resolution measure | 25 cm | 12.5 cm |
| --- | ---: | ---: |
| Dense material bytes | 6,291,456 | 50,331,648 |
| Encoded material bytes | 623,726 | 2,494,668 |
| Packed vertex bytes | 1,230,816 | 4,627,104 |
| Greedy quads | 25,642 | 96,398 |
| Generation p50 / p95 (ms) | 0.70 / 2.33 | 3.38 / 5.58 |
| Meshing p50 / p95 (ms) | 6.12 / 25.61 | 62.35 / 80.06 |

Halving cell width multiplies the dense volume by eight, but this fixture's run storage by about four. Surface geometry and cold meshing also cost more; these timings are one CPU run, not phone FPS. CPU/GPU residency limits remain unchanged. The finer density is an opt-in comparison, not a claim of an approved device budget. Compare **Root site → 25 cm / 12.5 cm** without changing the camera, then zoom closer. `?cell=0.125` retains the comparison on reload; exports identify the density.

The quarter-metre baseline, simple lighting, small extent and provisional camera do not match John Lin's engine density/lighting. Human visual approval and real tablet/phone GPU testing remain gates before scaling beyond this **bounded comparison**. Natural terrain remains non-editable. No production renderer choice or planet-scale claim is made.

### Regional seed survey

In **Field notes**, choose 256 × 256 m and enter a seed; `?extent=256&seed=39` retains that choice after reload. **Region** centres a viewport over the new area; **Root site** returns to the same ferrite deposit. The regional view shows only a cache-bounded portion, not the entire footprint. The 128 m default still loads unless explicitly selected.

Run `node tools/survey-microvoxel.cjs 256 0.25` (or `256 0.125`) to sample seven seeds on a 4 m grid, assert repeatable ground/chunk bytes and root geology, and report fingerprints for heights, river corridor, surface water, exposed rock and root locations. The first survey found **7 distinct height fields, 1 river corridor, 1 exposed-rock pattern and 1 root location** at 25 cm; water coverage varies slightly with seeded height. Thus the extension and surface variety are testable, **but the macro world generation is still a fixed river/ridge/clearing template**, not diverse worlds or resource placement. This should guide the next generator iteration rather than be hidden by larger map dimensions. These are sampling checks, not proof of phone performance or visual quality.

`node tools/benchmark-microvoxel.cjs 2718 0.25 256` benchmarks 64 chunks entirely beyond the original boundary; unlike a whole-world estimate, this shows the actual cost of generating an equal physical patch in the expanded region. The chunk origin is in its JSON output; browser viewport, loading and cache estimates are separate.

## Infinite streaming experiment

Choose **Field notes → World footprint → Infinite streaming experiment → Generate**, or open `?extent=infinite&seed=2718`. Both finite footprints remain available; 128 m / 25 cm is still the default. This mode uses a separate **`micro-wilds-12`** generator and root identity, leaving the finite generator's material fixtures unchanged. Seeded ridge, fracture and wet-corridor fields vary across coordinates and seeds, plus a seeded massif (stepped plateaus, cliff walls and passes) and a gorge; see Geography below for routed rivers and the first fantasy landforms.

**Geography (`micro-wilds-12`).** Seeded plates (about 640 m apart, continental or oceanic, each drifting) shape the streamed world: colliding continents raise ranges up to about 200 m, sharpened by ridged crag detail into arêtes and summits, ocean-under-continent margins give coastal ranges and trenches, divergence opens rifts, and oceanic crust sits below sea level as open sea. Boundaries are evaluated pairwise so relief stays continuous through triple junctions. Climate comes from latitude, altitude lapse, banded prevailing winds and upwind moisture (rain shadows behind ranges) on a cached 32 m grid; biomes set surface materials and tree density. Streamed columns hold 1,024 cells (256 m at 25 cm) and meshing stops at each chunk's highest occupied cell. Sea hexes are never offered as frontier. Finite 128 m and 256 m worlds are byte-identical to before. Rivers come last: a priority-flood drainage pass on a jittered 64 m node grid (2 km tiles, 1 km margin) fills pits into lakes, routes every node downhill to the sea (the home massif is part of the routed surface, so rivers go around it), sizes rivers by upstream area and cuts them into the final terrain. Each river sits in a valley whose width grows with the height of the ground beside it, so rivers through mountains run in V-valleys rather than slots. Zooming out past the voxel view (up to 2 km across) switches to a continent view: 32×32-column heightfield tiles of 1–16 m columns sampled from the same geography, built in the worker and cached separately.

**Mountains (`micro-wilds-12`).** Ridges are domain-warped and clustered into massifs between lower cols. Temperature falls 0.17 °C per metre. Mountains zone like the Cascades or Rockies:
- **Montane conifer forest:** the lower slopes. Open pine on the drier side, and forest stays on slopes up to about 58°.
- **Subalpine parkland:** small conifers in green meadow.
- **Alpine meadow:** above the trees.
- **Snow:** sticks to everything under about 60°. Below the snowline, rock starts at about 55°.
- **Glaciers:** in cold mountain ground, ice fills hollows up to a smooth surface, so ridges and summits stand out as rock and snow. The upper glacier is snow-covered and the lower glacier is bare ice.
- **Stratovolcanoes:** one candidate per 700 m cell on the land side of subduction margins and in island arcs. Each is a 110–190 m cone with a summit crater and radial gullies that hold radiating glaciers. Volcanoes are part of plate relief, so rivers route around them and they cast rain shadows.

**Landform and fantasy (`micro-wilds-12`).** Bare rock follows landform only: gorge lips, massif tier rims, thin fault seams, small outcrop knolls (2–4.5 m, commoner below the massif cliffs), cliff-steep mountainsides and alpine ground. Grassland, forest and plateau tops stay vegetated. Mountains zone from forest to rock to snow by altitude, and snow lies on everything except cliffs. Two fantasy features: **sky isles**, aether-lifted slabs that hover 20–50 m above the highest ground beneath them (commoner over mountain belts), with a crystal keel under each and a shadow cast on the ground; and **aether crystal spires**, clusters of leaning violet pillars on a ring of aether moss, mostly in mountains and beside gorges. Both are scenery: ground queries, crossings and barriers ignore them. The view centres on the explorer's altitude, re-centring smoothly when travel climbs or descends more than 10 m.

**Unified LOD (`lod-stream.js`).** The streamed world has one voxel system from 8 m to 2 km across. Finite 128/256 m fixtures keep the chunk path above.

- **Nodes.** A node is 32×32 columns at level L, one world column sampled every 2^L cells (25 cm to 8 m columns at 25 cm density; 8 m to 256 m nodes). Each column is built with the real column generator (ground, trees, isles, spires, ore) and reduced vertically by keeping each block's top occupied material. Building at a level's own spacing costs about the same per node at every level (6–25 ms), about 7× less per area than meshing full-resolution chunks at a coarse step.
- **Level choice.** Automatic level targets about two device pixels per column (four in Economy). If the visible nodes would not fit comfortably in the budget, it coarsens. Evicting a node the view still needs (tall terrain makes larger nodes) also coarsens one level until the next discrete move (jump, root, reload).
- **Loading.** Up to four workers (hardware threads − 1) build nodes nearest the view centre first. A visible area with nothing drawable gets its ancestor two levels up first, so a fresh view fills quickly and then sharpens.
- **No holes, no seams.** Until a node is ready, the lowest ready ancestor that covers its whole group is drawn instead (or still-cached finer nodes when zooming out), so a group swaps to finer detail all at once. Nodes that replace something dissolve in over 0.25 s while what they replace dissolves out on the same screen-space dither. Node borders carry skirts: halo columns stop two blocks below the lower side, so each border has a short wall that covers height mismatches against a neighbour at another level.
- **GPU budget.** Desktop 1 GiB; touch devices 512 MiB with ≥ 6 GB reported RAM (`navigator.deviceMemory`, Chromium only), else 384 MiB; Economy 128 MiB; `?gpuMiB=` overrides. Nodes on screen or fading are retained over others when the cache evicts.
- **Benchmark.** `node tools/benchmark-lod.cjs` builds a fixed mix of nodes (every level, lowland and mountains) and reports ms per node by level with the stage breakdown. `--against <git-ref|file>` builds the same nodes with another version of the generator and reports the speed ratio. When the generator version matches, it also checks that world data and node surfaces are unchanged; it exits non-zero if they differ.
- **Timing.** Performance shows where terrain time goes: per-node worker stages (geography, trees, isles/spires/ore, vertical reduce, greedy mesh), main-thread view update, draw-list rebuild, draw submit and GPU upload, plus GPU terrain time where `EXT_disjoint_timer_query_webgl2` is exposed.

- Navigation stores signed 8 m chunk coordinates plus local metre offsets in `[0, 8)`: `{cx, cz, x, z}`. Negative boundaries normalize rather than wrapping. URL parameters `cx`, `cz`, `lx`, `lz` retain this compact location alongside mode, seed and density. Density changes keep the logical location and root identity but re-quantize ground.
- **Clean cliffs.** Massifs fade out over the 30 m beside rivers instead of being cut off, pass mouths flare at the massif foot, and a raised strip only one or two voxels wide takes the height of its lower neighbours, so cliff lines carry no free-standing slivers. Hex outlines are draped once per voxel and step straight up and down walls.
- **Terrain barriers.** Each hex samples a 1 m grid. A gorge floor, or a 2.5 m step that splits the hex so that less than 85% of it is one walkable patch, makes it an impassable `cliff`/`gorge` barrier; `pass` and `highland` hexes stay passable (passes cost +2). Every barrier has hidden `sound`/`fractured` rock. Barriers are judged per hex, not per edge, so a wall lying exactly along a hex border can still be stepped across between two passable hexes (about 4% of passable neighbour pairs in the seed survey). `node tools/survey-microvoxel.cjs infinite` checks every surveyed seed opens onto passable ground with a barrier within 5 hexes.
- **Crossings in co-op.** Exploration scouts a barrier edge (1 supply) instead of surveying it; the rock sample goes to Research, the measurement to Logistics at dusk. Logistics spends spare build points on one crossing at a time over several days: switchback ramp (cliff, 4 sound / 6 otherwise, travel 4), cutting (cliff, sound rock only, 7, travel 1.5) or bridge (gorge, 5 / 8, travel 1.5). Only then do routes, surveys and crew pass. Crossings are drawn as glyphs over the unchanged terrain. Plateau, pass and gorge-rim finds are richer uplift seams (yield 9–11).
- One articulated explorer stays at render X/Z zero. Dragging moves terrain under them; arrows travel, **Surroundings** widens the current view, and **Root site / R** returns home. Field notes also provides a chunk-centre jump for testing distant coordinates. This is free traversal: slopes, vegetation and water do not obstruct movement, and there is no route/collision simulation.
- Chunk origins sent to WebGL are `(chunk - playerChunk) * 8 - localOffset`. CPU generation/ground queries use logical coordinates, but GPU positions remain local. Surface-detail coordinates are bounded separately; a distant selection/root marker projects relative to the current explorer.
- Residency: LOD nodes live in one GPU cache capped by bytes (below) and 16,384 entries, plus **2,048 memoized vegetation entries per world instance** (main thread and each worker). There is no visited-node collection. Returning after eviction regenerates the same nodes; cold terrain can visibly stream in again. These are explicit buffer/cache limits, not whole-process memory measurements.
- “Infinite” means on-demand generation, **not literal infinity**. Navigation and chunk generation stop at **±16,777,215 chunks** (about ±134,218 km); movement clamps there rather than wrapping. Terrain is immutable. Only the URL location persists: discoveries, buildings, edits and world-wide history are not stored.

`node tools/benchmark-microvoxel.cjs 2718 0.25 infinite` samples 64 chunks starting at `(1000000, -1000000)`—8,000 km from zero on each axis. Optional final arguments select a different chunk origin. The same full-resolution patch encoded **580,112 bytes** at 25 cm and **2,320,106 bytes** at 12.5 cm in this fixture, versus 6,291,456 / 50,331,648 dense bytes. These are storage measurements, not device FPS results. Automated regressions cover signed rebasing, distant/guardrail-near travel, return-image equality after eviction, URL reload, density, GPU position bounds, portrait LOD/cache pressure and the offline package. The earlier iOS Simulator results concern the finite world; **streamed-mode iOS and physical-device performance are unverified**.

## Co-op supply line

The first playable slice on the hex atlas (OpenSpec: `openspec/changes/add-coop-supply-line`). Up to three players split **Exploration**, **Research** and **Logistics** through a night → day → dusk clock; information moves between roles only at phase turns, and unclaimed seats run on autopilot. The camp's Ferrite root meets the day-1 target (`6 + 3×(day−1)`) but not day 3, so the group must survey, identify and connect a second line. Numbers in `coop-session.js` are illustrative defaults.

- `coop-session.js` — host-authoritative, deterministic rules and role-private views (no DOM).
- `coop-net.js` — room transports: `peerjs` (default; host peer id `spacology-supply-<CODE>` on PeerJS's free public signaling service) and `local` (BroadcastChannel, same-browser tabs; `?coopNet=local`).
- `coop-play.js` — panel UI, hex actions and phase-driven crew.
- `vendor/peerjs-1.5.5.min.js` — PeerJS 1.5.5, MIT (`vendor/peerjs-LICENSE`), vendored so the page needs no CDN.

Terrain is never sent: every peer regenerates it from the shared seed. There is no game server, TURN relay, reconnect or save: if the host leaves the room ends, and strict NATs/carrier networks may fail to connect directly. A manual check opened a PeerJS room between two isolated headless browser contexts (join, night → day, leave → autopilot, unknown code); that is not run in CI and is not a mobile-network result.

## Verification and portable copy

```sh
npm test -- microvoxel-world
node tests/unit/coop-session.cjs
node tools/benchmark-microvoxel.cjs 2718
node tools/benchmark-microvoxel.cjs 2718 0.125

```

The last command packages the **same** source/model/worker into a single HTML (Blob worker); it does not rebuild or substitute a mock simulation. The bundled library link goes to the public library. Tests cover source and packaged/offline operation. Browser tests are headless unless explicitly requested otherwise. No new linter/type checker is configured for the plain-JS lab; syntax, model and browser tests complement the existing Svelte check/release gates.

### iOS launch path

The original package was tested on **iPhone 17 Pro Simulator / iOS 26.5**: native Files/Quick Look stalled, while the identical bytes served over HTTP rendered in actual Safari and supported crew/pause. The preview's execution failure was not explained, and this is not a physical-device performance result. For iOS, use a hosted Safari page rather than promising downloaded-file preview support. The static startup notice makes that limitation visible even if the runtime never begins. Hosting/deployment is separate from creating the portable copy; this PR does not automatically deploy a preview.
