## Context
Reuse the existing static prototype/library/Pages and Node/headless Playwright infrastructure. Existing terrain studies do not supply the requested microvoxel representation. Keep this proof independent and use WebGL2 without adding a second build pipeline or external runtime dependency. This is a bounded surface-world experiment, not a general destructive voxel engine.

## Decisions
- Metres, Y up, 128 × 128 m catchment. Default 0.25 m cells use 32-cell horizontal chunks / 96-cell vertical extent; optional 0.125 m cells use 64 / 192. Both retain 8 × 8 × 24 m chunk volumes and metre-scale world features. Stable seed/generator/world IDs; a separate data ID includes cell size. Generation is a coordinate function, not an advancing random stream.
- Immutable vertical material runs preserve air gaps, trunk/leaf volumes and geological strata without a dense volume per resident chunk. All occupancy reads use these runs. Ground queries exclude non-walkable vegetation. There is no terrain mutation API.
- Generate transient dense samples only for meshing. Greedy merge same-material coplanar faces; query the neighbouring chunk's world coordinates for border visibility. Upload typed vertex buffers, not individual voxel objects.
- One worker, one request in flight, view-prioritized queue; transfer mesh buffers. Bounded LRU CPU/GPU cache, evict and dispose buffers; stale results cannot repopulate another seed/view. Uniform far LOD avoids adjacent mixed-resolution cracks. LOD samples the same authoritative world but is not a ground/buildability source.
- Orthographic fixed 50° downward tilt, 35° fixed azimuth (prototype, not final camera approval), drag/keyboard pan and buttons/wheel zoom. No perspective/free-flight. Reduced motion stops limb/water oscillation; pause stops actors.
- Dragging uses the camera's inverse projection: a fixed terrain landmark follows the finger/cursor in both screen axes. Density changes retain camera framing and resource X/Z/identity but regenerate voxel-ground quantization; camera LOD never changes that selected truth. Both caches and metrics reset on density changes; stale replies are rejected. The 25 cm baseline stays default while the finer density is measured.
- When zoom changes LOD, keep drawing the previous meshes at the current camera until every destination mesh for the visible view is resident; then switch the entire view atomically. The GPU cache remains bounded, and previously unseen or evicted chunks may still stream while a transition is pending. Do not add a second framebuffer or remesh the old terrain per frame.
- Voxel characters use reusable articulated-part buffers; no terrain remeshing for animation. Height follows voxel-derived walkable ground.
- Deposit provenance records the exposed-rock/fault rule. This lab intentionally surveys one root; zoom never reveals another deposit. No claim of Exploration/Research integration.
- Render targets: <=320 resident mesh chunks, <=32 MiB mesh cache, pixel ratio capped at 1.5, optional economy mode. Report CPU typed-array and GPU-buffer estimates separately from unknown whole-process memory. Frame intervals are not GPU timestamps. No phone-performance claim from the VM.

## Risks / Tradeoffs
Column RLE favors mostly static terrain, not arbitrary mutation. Coarse rendering sacrifices detail and may visually shift surfaces by one sample; exact ground and deposit positions remain authoritative. Raw WebGL is deliberately small and replaceable. This proof cannot match a specialist engine's lighting and planet scale. Visual quality and real device budgets require Jacob's approval.
